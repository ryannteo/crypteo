# V2 release run (v2.0.0)

## Summary

At the `v2.0.0` commit, Crypteo researched one historical hour three ways on real
Coinbase Exchange data: the V1 release candidate (BTC-USD at 2026-10-15T13:00:00Z)
as an opportunity-led evaluation window on Claude Opus 5.5, and the same hour as
trader-led research on Claude Opus 5.5 and on Claude Haiku 5.5. A fresh download
reproduced the V1 release's dataset versions exactly. A separate process with no API
key reproduced the evaluation window from the stored artifacts and reloaded both
trader-led runs. A fresh clone of the commit reproduced the code identity recorded
by all three runs. All three runs returned NO_TRADE. This shows end-to-end operation
of both V2 themes, reproducibility and auditability; it is not a performance result.

## How the window was chosen

The window was not chosen fresh: it is the candidate the V1 release had already
inspected, so the two releases can be compared on the same input. `plan_windows`
with purpose `EVALUATION`, `planning_start` 2026-10-15T13:00:00Z and limit 1 found
exactly one candidate, BTC-USD at 13:00, and selected it with the window
[13:00, 19:00]. Plan ID
`sha256:172135ad36aa806270d2aefd49478d55a0ef5383c67ab016cfd41fadf1c43c33`. The run
script refused to spend unless the plan selected exactly that candidate.

## Procedure and checks

1. The download was checked against the V1 dataset versions before any spend.
2. The Haiku trader-led run, then the Opus evaluation window, then the Opus
   trader-led run, each from a clean tree at the release commit with version 2.0.0
   installed; the script refused to run otherwise.
3. Each trader-led run passed six checks, live and again after reload:
   - every prompt version was trader-led;
   - tool-offering requests offered relative strength against ETH-USD and SOL-USD;
   - requests offered no tools carried the tool definitions;
   - the question appeared only in the request context;
   - every tool query was for BTC-USD;
   - the run completed with a model assessment.
4. With `ANTHROPIC_API_KEY` unset, `reproduce_evaluation` replayed the baseline
   exactly and the research from the stored artifacts. Candidate decisions and
   metrics matched. Both trader-led runs reloaded through `load_terminal`, with
   `inspect_run` state `COMPLETED`.
5. The current checkout and a fresh clone of the commit each computed the code
   identity above, and all three stored runs recorded the same identity.

All checks passed. The release-run script used only the public APIs and is not part
of the repository.

## Results

| Run | Decision | Confidence | Model calls | Re-asks | Tool attempts | Input tokens | Output tokens |
|---|---|---|---|---|---|---|---|
| Opportunity-led, Opus | NO_TRADE | 66 | 12 | 0 | 8 of 8 | 76,060 | 9,722 |
| Trader-led, Opus | NO_TRADE | 55 | 12 | 0 | 8 of 8 | 80,385 | 12,594 |
| Trader-led, Haiku | NO_TRADE | 55 | 7 | 0 | 3 of 8 | 38,188 | 15,275 |

Tools called, in order:

- Opportunity-led, Opus: `lower_band_crossings`, `trend`, `higher_timeframe`,
  `candle_structure`, `volume_context`, `momentum`, `levels`, `volatility`.
- Trader-led, Opus: `trend`, `momentum`, `higher_timeframe`, `bollinger_position`,
  `lower_band_crossings`, `volume_context`, `candle_structure`, `relative_strength`
  against ETH-USD.
- Trader-led, Haiku: `trend`, `momentum`, `higher_timeframe`.

The following paraphrases the stored outputs, with short quotations:

- **Opportunity-led, Opus.** "The evidence is sufficient to reject this long
  candidate for further consideration." The model found the trend bearish on the
  hourly, 4h and daily views, a trigger candle closing near its low with no
  rejection, and no edge in the trigger's own history (17 samples, 47% higher after
  6 bars, median return about -0.10%). The critic noted that the band cross was
  marginal (about 0.05%), that `bollinger_position` was available but not requested,
  and that momentum was mixed rather than decelerating; the assessment accepted
  these corrections.
- **Trader-led, Opus.** The evidence "on balance argues against" a long, with
  moderate confidence. The critic caught a factual misreading in the thesis: a
  candle's close location, a fraction of its range (0.0148), had been reported as a
  1.5% price distance. The assessment corrected it, treated the crossing history as
  neutral rather than bearish, and noted that BTC-USD outperformed ETH-USD over 24h
  but not over 6h.
- **Trader-led, Haiku.** The model stopped after three of its eight tool attempts.
  The critic noted that the conclusion rested on three of ten evidence sets, and the
  assessment kept NO_TRADE at moderate confidence while listing the missing
  evidence.

The V1 release, under the V1 research policy, assessed the same candidate as
NO_TRADE with confidence 58 using 155,566 input tokens.

## Limitations

- One candidate, already inspected by the V1 release, researched three ways. It is
  not a performance evaluation and supports no claim about research quality or
  trading skill.
- The trader-led question was written after T. ADR-014 excludes trader-led runs from
  evaluation for this reason, and these runs show the trader-led path working, not
  research quality.
- The Haiku run is a plumbing check of the trader-led path. Opus 5.5 at effort
  `high` is the reference setting for trader-led research whose answer is read as
  research.
- The evaluation window bound only BTC-USD, so its run had no relative-strength
  evidence. The trader-led runs bound all three pairs.
- An LLM's parametric knowledge cannot be proven point-in-time pure. The window is
  after the model's stated training cutoff, which does not prove the model has no
  knowledge of it.
- Licensed raw Coinbase data is not redistributed. Frozen reproduction requires the
  same code identity and the same Python and Pydantic versions.

## Found during the release

No code defect was found. Three research observations recurred from the July 2026
trials:

- The opportunity-led run did not request `bollinger_position`, which its critic
  noted. No trial-6 window requested it either.
- Both Opus runs puzzled over a 4h 20-block low sitting below the daily 20-block low.
  Each view's window definition is not visible to the model, the same gap trial 6
  cited in 8 of 10 windows.
- The Opus trader-led run was unsure whether the pending crossing was the current
  candle, although the `lower_band_crossings` description states the pending rule.

# V1 release run (v1.0.0)

## Summary

At the tagged `v1.0.0` commit, Crypteo ran fresh Claude research on real Coinbase
Exchange hourly data through the public historical research replay API, storing
every model call, tool resolution and stage output in a durable research store.
A separate process with no API key then reproduced the replay from the frozen
artifacts alone, with no inference, and matched the fresh run's financial records,
portfolio, metrics and research outcomes exactly. The run covered one replay window
and one research run; it shows end-to-end operation, reproducibility and
auditability on real data, not trading performance.

## How the window was chosen

The window was chosen mechanically, before any research ran:

1. One point-in-time scan of each pair's full history found every lower-band
   crossing.
2. Crossings without at least 72 hours of complete history before them, and complete
   data through the window end, were dropped.
3. The scanner-only baseline was run on each remaining single-asset window
   (85 windows).
4. Windows were ranked by complete lifecycle first (the admitted candidate reached
   an exit), then by fewest research runs, then by recency.

Profit and loss was not a ranking criterion. The chosen window ranked first; it
admits one candidate (BTC-USD at 2026-10-15T13:00:00Z), so the research replay needed
exactly one research run (`max_research_runs=1`).

## Procedure and checks

1. Fresh research replay (`FRESH_INFERENCE`) into a durable SQLite research store,
   then `load_research_replay` to reload the result and validate its research links
   against the store.
2. Frozen reproduction in a separate process with no `ANTHROPIC_API_KEY` set, using
   the same code identity and Python/Pydantic versions. It replayed twice from the
   stored artifacts and checked that:
   - the two frozen runs are byte-identical;
   - financial records, final portfolio and metrics equal the fresh run's, with
     order IDs excluded: they derive from the manifest-bound run ID, which
     legitimately differs between the FRESH and FROZEN settings;
   - research metrics and research records equal the fresh run's;
   - the frozen result reloads with validated research links, and the research
     artifact round-trips through the store with the same checksum.
3. A fresh clone of `v1.0.0` reproduced the run's code identity (commit and source
   digest) exactly.

All checks passed. The scripts that drove these steps used only the public APIs and
are not part of the repository.

## Result

The single research run assessed the BTC-USD LONG candidate at
2026-10-15T13:00:00Z and returned **NO_TRADE** with confidence 58.

Tools called, in order (8 calls, the per-run maximum):

1. `trend`: success
2. `momentum`: success
3. `levels`: success
4. `volume_context`: success
5. `bollinger_position`: success
6. `relative_strength` against ETH-USD: unavailable
7. `volatility`: success
8. `relative_strength` against SOL-USD: unavailable

Both `relative_strength` calls returned `SOURCE_UNAVAILABLE` because the replay
contained only BTC-USD, so no ETH-USD or SOL-USD source was bound. The model
recorded both as remaining gaps.

The run made 12 model calls (9 investigation, then one each for thesis, critique and
final assessment), totalling 155566 input tokens and 9807 output tokens.

The following is a paraphrase of the model's stored outputs, with short quotations:

- **Thesis (model).** The 1h close (80445.43) crossed just below the lower Bollinger
  band (%B about -0.025), but trend and momentum were bearish across horizons and
  volume and volatility were elevated. Bounce-supportive signals were limited to a
  slowing 6h decline and proximity to the 24h low. The model concluded that the
  evidence "leans toward trend continuation rather than a clean mean-reversion
  setup", and listed the missing benchmarks, confirmation bars and higher-timeframe
  context as gaps.
- **Critique (model).** The critique accepted the thesis's bearish lean but
  challenged its bull case: the claimed deceleration is undercut by the trigger bar
  being the sharpest recent drop, the 24h low is "only a window minimum with no
  reaction evidence", and the %B penetration is marginal with no base rate. It also
  noted that all evidence came from one Coinbase 1h dataset with overlapping
  windows.
- **Decision (model).** "The LONG mean-reversion candidate is not supported by the
  supplied evidence." The model accepted the critique, judged that the gaps limited
  confidence but provided no support for the LONG, and chose NO_TRADE over ABSTAIN
  because the available evidence was coherent enough to reject the candidate.

## Limitations

- This is one window and one research decision (n=1). It is not a performance
  evaluation and supports no claim about trading skill.
- The replay contained a single asset, so the run produced no cross-asset evidence;
  both relative-strength requests were unavailable.
- An LLM's parametric knowledge cannot be proven point-in-time pure, and this run
  does not establish whether the window postdates the model's training data. See the
  [README caveat](../../README.md#architecture).
- Licensed raw Coinbase data is not redistributed, so a third party must run their
  own acquisition; their dataset versions will match only if Coinbase returns the
  same candles. Frozen reproduction also requires the same code identity and the
  same Python and Pydantic versions, because both are part of the replay identity.
- The release-run scripts are not part of the repository.

## Found during the release

The shipped Coinbase transport sent Python's default `urllib` User-Agent, which
Coinbase rejects with HTTP 403. Tests could not catch this because no test touches
the network: Coinbase access goes through an injected transport. Commit `92e3f4f`
added an identifying User-Agent before the run, and that commit is the one tagged
`v1.0.0`.
